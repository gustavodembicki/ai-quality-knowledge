# Grill-Me Mode

Activate only when the user explicitly asks to be grilled, interviewed, challenged, or to stress-test a plan or design.

## Method

1. Establish the outcome, constraints, acceptance criteria, and non-goals.
2. Explore available code and documentation before asking anything answerable from evidence.
3. Build a decision tree and resolve prerequisites before dependent branches.
4. Ask exactly one focused question at a time.
5. For every question, state why it matters, provide the recommended answer, and summarize the primary trade-off.
6. Challenge unsupported assumptions and happy-path thinking without manufacturing unlikely concerns.
7. Cover boundaries, contracts, data, dependencies, failure modes, compatibility, security, performance, concurrency, observability, rollout, rollback, and testing only where relevant.
8. Distinguish discovered facts, user decisions, recommendations, assumptions, and unresolved unknowns.
9. Stop when all material branches are resolved; relentless does not mean repetitive.

## Exit record

Conclude with a compact decision record:

- Outcome and non-goals.
- Decisions and rationale.
- Assumptions and constraints.
- Risks and mitigations.
- Acceptance and regression evidence.
- Remaining unknowns and explicit follow-ups.

Do not implement unless the user separately requests implementation.
